## มันคืออะไร

[Agent Skills](/docs/agent-skills) — โฟลเดอร์ที่มี `SKILL.md` — คือมาตรฐานเปิดที่เผยแพร่ไว้ที่
[agentskills.io](https://agentskills.io) ไม่ใช่สิ่งที่ผูกขาดเฉพาะ Claude Code เครื่องมือ AI
coding ใดก็ตามที่รองรับสเปกนี้สามารถโหลดโฟลเดอร์ skill เดียวกันได้ ความเป็น portable นี้เองที่ทำให้
ecosystem ของบุคคลที่สามเกิดขึ้นได้ — คนเขียน skill ครั้งเดียวแล้วแชร์เป็น git repo เหมือนที่คุณแชร์
npm package หรือ Terraform module

**skills.sh** เป็นหนึ่งใน directory แบบนี้ — แคตตาล็อกและ leaderboard สำหรับ skill package สร้างโดย
Vercel ควบคู่กับ CLI (`npx skills`) มันเป็น **โปรเจกต์ของบุคคลที่สาม ไม่ใช่ผลิตภัณฑ์ทางการของ
Anthropic** ให้ถือว่ารายละเอียดเฉพาะเจาะจงในหน้านี้เป็นข้อมูลประกอบมากกว่าจะเป็นแหล่งอ้างอิงที่
แน่นอน — มันเป็นพื้นที่ที่ยังใหม่และเปลี่ยนแปลงเร็ว และนิสัยการนำมาใช้อย่างปลอดภัยด้านล่างสำคัญกว่า
ฟีเจอร์ปัจจุบันของเครื่องมือใดเครื่องมือหนึ่ง

<Note type="warning">
  หน้านี้ตั้งใจให้มีข้อกำหนดน้อยกว่าหน้าก่อนหน้า เอกสารของ Anthropic เองครอบคลุม *กลไก* — `SKILL.md`
  พร้อม frontmatter, วิธีที่มันถูกค้นพบและโหลด — อย่างละเอียด และนั่นคือสิ่งที่
  [Agent Skills](/docs/agent-skills) ยึดโยงอยู่ ชั้น marketplace ที่อยู่ด้านบนนั้นถูกดูแลโดยชุมชน
  เปลี่ยนรูปแบบบ่อย และไม่ใช่สิ่งที่ควรเชื่อตามข้อมูลที่ training มาแบบไม่ตรวจสอบ ให้ตรวจสอบ
  รายละเอียดปัจจุบัน (ขั้นตอนการติดตั้ง นโยบายคัดกรอง สิ่งที่กำลังนิยม) โดยตรงก่อนจะพึ่งพามัน
</Note>

แนวคิดหลักที่ควรจำไว้ ไม่ว่า marketplace tool เฉพาะเจาะจงตัวไหนจะเป็นที่นิยมตอนที่คุณอ่านอยู่:
**การติดตั้ง skill จากบุคคลที่สามหมายถึงการนำคำสั่งของคนอื่น — และอาจรวมถึง script ของคนอื่น —
เข้ามาอยู่ใน context และเส้นทางการทำงานของ Claude โดยตรง** นั่นคือ trust boundary ที่ต่างจากการ
ติดตั้ง library และเป็นเหตุผลที่หน้านี้แยกออกมาจากหน้ากลไก

## ใช้งานอย่างไร

### รูปแบบทั่วไปของการติดตั้ง skill จากบุคคลที่สาม

ไม่ว่าจะเป็น marketplace ไหน รูปแบบก็เหมือนกันเพราะมันตามมาจากวิธีที่ skill ถูกค้นพบโดยตรง (ดู
[Where skills live](/docs/agent-skills#where-skills-live)):

1. หา skill ใน directory หรือ public git repo
2. ขั้นตอนติดตั้งจะคัดลอก (หรือ symlink) `SKILL.md` และไฟล์สนับสนุนของมันเข้าไปใน
   `~/.claude/skills/<name>/` (ส่วนตัว ใช้ได้ทุกที่) หรือ `.claude/skills/<name>/` (scope เฉพาะ
   โปรเจกต์ commit เข้า repo)
3. Claude Code จะรับรู้มัน — ทันทีถ้า skills directory มีอยู่แล้วตอน session เริ่ม หรือหลัง restart
   ถ้าเป็นโฟลเดอร์ skills ระดับบนสุดที่เพิ่งสร้างใหม่

CLI installer อย่าง `npx skills add <owner>/<repo>` ทำให้ขั้นตอนที่ 2 เป็นอัตโนมัติ แต่ไม่มีอะไร
วิเศษเกี่ยวกับมัน — มันก็แค่ไฟล์ที่ไปอยู่ใน directory ที่ Claude Code เฝ้าดูอยู่แล้ว คุณสามารถได้
ผลลัพธ์เดียวกันด้วยการ clone repo แล้วคัดลอกโฟลเดอร์เอง ซึ่งควรจำไว้เมื่อคุณอยากตรวจสอบก่อน
ติดตั้งแทนที่จะเชื่อพฤติกรรม default ของ installer

### การเรียกดูและการค้นพบ

Marketplace ที่สร้างบนมาตรฐาน Agent Skills โดยทั่วไปจะมี:

- Directory ที่ค้นหาได้ของ skill มักมาพร้อมจำนวนการติดตั้งหรือ leaderboard เป็นสัญญาณคุณภาพคร่าว ๆ
  (คร่าว ๆ จริง — จำนวนติดตั้งสะท้อนความนิยม ไม่ใช่ความถูกต้องหรือความปลอดภัย)
- Skill แบบ `find-skills` ของตัวเอง ให้ Claude ค้นหา marketplace ให้คุณจากภายใน session และ
  แนะนำ skill ที่ตรงกับสิ่งที่คุณกำลังทำ
- ไม่มี review gate ที่เป็นทางการสำหรับการส่ง skill จากชุมชน ต่างจากคอลเลกชัน skill ขนาดเล็กที่
  คัดสรรเองของ Anthropic ที่
  [github.com/anthropics/skills](https://github.com/anthropics/skills) ความแตกต่างนี้ —
  คัดสรรและเล็ก กับ เปิดและใหญ่ — คือสิ่งที่ควรจำไว้เวลาตัดสินใจว่า skill หนึ่ง ๆ ควรถูกตรวจสอบ
  มากแค่ไหนก่อนติดตั้ง

### การเผยแพร่ skill ของคุณเอง

เพราะ skill คือแค่ directory ที่มี `SKILL.md` ใน git repo "การเผยแพร่" จึงใกล้เคียงกับ "push มันไป
ที่สาธารณะแล้วบอกคนอื่นให้ไปดู" marketplace ที่สร้างบน install telemetry อาจ list skill ของคุณ
อัตโนมัติทันทีที่คนเริ่มติดตั้งจาก repo ของคุณ โดยไม่มีแบบฟอร์มส่งแยกต่างหาก — ซึ่งย้อนกลับมาอีกด้าน
เช่นกัน: **การถูก list ไม่ใช่การถูกตรวจสอบ** การปรากฏใน directory ไม่ได้แปลว่ามีใครรีวิวเนื้อหาของ
skill นั้น

ถ้าคุณกำลังเผยแพร่ ไม่ใช่แค่ใช้: เก็บ `allowed-tools` ให้แคบเท่าที่ skill ต้องการจริง ๆ (ดู
[Agent Skills](/docs/agent-skills#frontmatter-fields)) เขียนอธิบายว่า skill ทำอะไรและไม่แตะ
อะไรด้วยภาษาธรรมดาเหนือ frontmatter ที่เป็น technical field และหลีกเลี่ยงการแนบ script ที่เข้าถึง
เครือข่าย เว้นแต่ `SKILL.md` จะระบุไว้ชัดเจน — คนที่ดูผ่าน ๆ ก่อนจะติดตั้ง skill ของคุณไม่ควรต้อง
อ่าน bundled Python script ทีละบรรทัดเพื่อจะรู้ว่ามันแอบส่งข้อมูลออกไป

## แนวทางที่ดี — การประเมิน skill ก่อนจะเชื่อมัน

นี่คือส่วนที่สำคัญกว่า UI ของ marketplace ใด ๆ skill คือ prompt content บวกกับ script ที่รันได้
บ่อยครั้ง — ประเมินมันแบบเดียวกับที่คุณประเมิน shell script ที่มีคนโพสต์ในฟอรัม ไม่ใช่แบบที่คุณ
ประเมิน package ที่เซ็นชื่อรับรองจาก official registry ของภาษาโปรแกรม

<Note type="danger">
  Skill สามารถขอ `allowed-tools` ที่ pre-approve คำสั่งได้ **โดยไม่มี permission prompt** และ
  script ที่แนบมาจะรันด้วยสิทธิ์เท่าที่ skill ให้ตัวเองไว้ อ่าน `SKILL.md` ก่อนติดตั้งเสมอ —
  อย่าข้ามเพราะคิดว่า "มันก็แค่ markdown file"
</Note>

- **อ่าน `SKILL.md` ทั้งหมดก่อนติดตั้ง โดยเฉพาะ frontmatter ของ `allowed-tools` /
  `disallowed-tools`** field นี้คือ skill ที่ pre-authorize ตัวเองให้รันคำสั่งเฉพาะโดยไม่ต้องถาม
  คุณทุกครั้ง skill ที่แค่ต้องอ่านไฟล์ไม่มีเหตุผลที่จะขอสิทธิ์ `Bash` แบบกว้าง
- **ตรวจสอบ script ที่แนบมาด้วย และอ่านมันด้วย** โฟลเดอร์ `scripts/` หมายความว่า skill สามารถรัน
  โค้ดตามใจชอบ ไม่ใช่แค่ prompt Claude ด้วยข้อความ ปฏิบัติกับ script ที่ยังไม่ได้ตรวจสอบเหมือน
  `curl | bash` จากแหล่งที่ไม่คุ้นเคย
- **เลือกติดตั้งแบบ project-scoped (`.claude/skills/`) มากกว่า personal
  (`~/.claude/skills/`)** สำหรับสิ่งที่คุณยังตรวจสอบไม่ครบ skill ระดับโปรเจกต์มองเห็นได้ใน repo
  review ได้ใน diff และ scope อยู่แค่ codebase เดียว — มันจะไม่แอบตามคุณไปทุกโปรเจกต์แบบที่
  personal skill ทำ
- **ตรวจสอบว่า workspace trust ของ skill นั้นหมายถึงอะไรสำหรับคุณ** Skill ระดับโปรเจกต์จะได้รับ
  สิทธิ์ `allowed-tools` *หลังจาก* คุณยอมรับ dialog trust workspace สำหรับโฟลเดอร์นั้นเท่านั้น —
  gate เดียวกับที่คุมกฎ permission ใน `.claude/settings.json` อย่ากด accept dialog นั้นผ่าน ๆ
  โดยไม่ได้อ่าน skill จริง ๆ ก่อน
- **เลือก skill เล็ก ๆ ที่ทำหน้าที่เดียวมากกว่าคอลเลกชันขนาดใหญ่รวมกัน** repo ที่โฆษณาว่ามี
  "300+ skills" คือ 300 อย่างที่คุณไม่ได้รีวิวทีละตัว ติดตั้งแค่ตัวที่คุณต้องการ ไม่ใช่ทั้งชุด
- **ระวังความเสี่ยง prompt injection ในสิ่งที่ skill ทำให้ Claude อ่าน** Skill ที่ดึงหน้าเว็บ
  คำอธิบาย PR หรือเนื้อหา issue แล้วป้อนกลับเข้า prompt กำลังเปิดให้ Claude เจอข้อความจากแหล่งที่
  ไม่มีใครควบคุมได้เต็มที่ นี่ไม่ใช่ปัญหาเฉพาะ skill จากบุคคลที่สาม แต่ skill ที่คุณไม่ได้เขียนเองคือ
  จุดที่สองที่ยังไม่ถูกตรวจสอบซึ่งรูปแบบนี้เกิดขึ้นได้
- **ตรวจซ้ำหลัง update** Skill ที่คุณตรวจสอบไปแล้วครั้งหนึ่งและติดตั้งทิ้งไว้อาจเปลี่ยนเนื้อหาใน
  `git pull` หรือติดตั้งใหม่ครั้งถัดไป ให้ถือว่า "ฉันตรวจแล้วก่อนหน้านี้" หมดอายุ เหมือนที่คุณควร
  ปฏิบัติกับ pinned dependency ที่คุณไม่ได้กลับไปอ่านซ้ำจริง ๆ

## ตัวอย่างจริง

วิธีที่ปลอดภัยในการลอง skill ที่เจอใน marketplace โดยไม่ต้องผูกมัดเต็มที่:

<Step>
  <StepItem title="ติดตั้ง แต่ scope ไว้ในโปรเจกต์ทดลอง">
    Clone repo ของ skill ด้วยตัวเอง (ข้าม installer CLI ในครั้งแรก) เข้าไปใน
    `.claude/skills/<name>/` ของโปรเจกต์ที่ทิ้งได้ ไม่ใช่ `~/.claude/skills/` วิธีนี้จำกัด
    blast radius ให้เหลือแค่โปรเจกต์ที่คุณยอมเสียได้
  </StepItem>
  <StepItem title="อ่าน SKILL.md ก่อนยอมรับ workspace trust">
    ตรวจสอบ field `allowed-tools` และ `disallowed-tools` โดยเฉพาะ แล้วเปิดไฟล์ทุกไฟล์ใต้
    `scripts/` ถ้ามันขอสิทธิ์เกินกว่าที่จุดประสงค์ของ skill ต้องการ ให้หยุดตรงนี้
  </StepItem>
  <StepItem title="เรียกใช้แบบระบุชัดเจน อย่าเพิ่งปล่อยให้ auto-invoke">
    ถ้า skill ยังไม่ได้ตั้ง `disable-model-invocation: true` ให้เรียกด้วยชื่อ (`/skill-name`)
    สองสามครั้งแรก แทนที่จะปล่อยให้ Claude ค้นพบมันเอง เพื่อให้คุณเห็นแน่ชัดว่ามันทำอะไรก่อนที่
    มันจะทำงานจากการเดา
  </StepItem>
  <StepItem title="เลื่อนขั้นอย่างตั้งใจ">
    หลังจากดูมันรันไปสักพักและอ่าน output แล้วเท่านั้น ค่อยย้ายไปที่ `~/.claude/skills/`
    เพื่อใช้ข้ามโปรเจกต์ หรือ commit สำเนาที่ scope โปรเจกต์เข้า repo เพื่อให้เพื่อนร่วมทีมได้
    รับ version เดียวกันที่ผ่านการตรวจสอบแล้ว แทนที่ต่างคนต่างติดตั้งจาก marketplace เอง
  </StepItem>
</Step>

นี่ช้ากว่า `npx skills add` แล้วใช้งานเลย — ตั้งใจให้ช้า คำสั่งติดตั้งแก้ปัญหาเรื่องการค้นพบ แต่
ไม่ได้แก้ปัญหาเรื่องความไว้ใจ และไม่มีเครื่องมือปัจจุบันตัวไหนทดแทนการอ่านสิ่งที่คุณกำลังจะให้สิทธิ์
เข้าถึง tool ได้
